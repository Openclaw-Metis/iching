# 卦辭與爻辭白話撰寫與審訂

2026-10-24 撰寫，內容存在 `src/data/lines.json`，共 450 條：64 條卦辭、384 爻、乾卦用九與坤卦用六。顯示在占卜解讀的主讀與輔讀，以及卡牌頁「經文」分頁每段卦辭與爻辭的下方。欄位與長度依規格「爻辭與卦辭白話內容規格」：`plain` 白話 60 到 140 字，`advice` 占得提醒 40 到 90 字。

## 這一輪與規格流程的差異

規格要求 Claude、Codex、agy 三方各自獨立撰稿，再交叉複審。這次撰稿的環境沒有 `codex` 與 `agy` 命令列工具，所以：

- 第一輪只有 Claude 的稿，`docs/review/lines-round1.json` 裡 Codex 與 agy 的欄位是空的。
- 第二輪是 Claude 依撰寫原則逐條自我複審，不是交叉複審。修改紀錄在 `docs/review/lines-round2.json`。
- 三方撰稿的流程已寫成 `.claude/commands/three-way-draft.md`。在有 `codex` 與 `agy` 的環境補跑時，以目前的 `lines.json` 當作 Claude 稿，讓另外兩方各自獨立撰稿後再比對定稿，並把結果寫回這份文件。

## 方法

1. **分批撰稿**：每批 8 卦，先讀該卦卦辭、彖傳、大象、六爻與小象，再寫卦辭與六爻的白話與提醒，乾坤另寫用九、用六。爻可引小象，卦辭可引彖傳與大象。
2. **逐批自動檢查**：每批寫完立刻檢查長度、「」引文與破折號，不合格就改到通過才寫下一批。
3. **自我複審**：450 條寫完後，依撰寫原則掃過全部提醒與白話，找出保證語氣、斷定現況、把人標成「小人」等問題逐條修改。
4. **自動測試**：`src/data/lines.test.ts` 核對 450 個鍵齊全、長度在範圍內、每段「」引文能在 `易經_周易_原文.md` 找到且斷句位置一致（以 `src/lib/text.ts` 的 `normalizeQuote` 正規化）、沒有破折號，並驗證 64 卦 × 64 種變爻組合的主讀與輔讀都找得到原文與白話，主讀的卦辭、爻辭、用九用六三種情況都實際出現（AC-05、AC-13）。

## 撰寫原則

沿用 `docs/content-review.md` 的撰寫原則：

- 引文一字不差，依本站底本用字與斷句，例如「莧陸夬夬」「井冽，寒泉食」「革言三就，有孚」「先庚三日，後庚三日，吉」。
- 不替讀者斷定現況，也不保證結果：提醒寫成「若……，可以……」「有助於」「比較有機會」，不寫「就會」「自然會」「終會」。
- 不給醫療、法律、投資的具體建議。无妄九五「勿藥有喜」寫明是比喻，並提醒真正的健康問題仍要就醫；中孚大象「議獄緩死」、旅大象「明慎用刑」點明是古代語境。
- 古代的性別、婚姻、身分與刑罰內容點明是古代語境，提醒轉譯成角色、責任與界線。
- 數字與方位不當成應驗的預言：「七日得」「三歲不覿」「十年乃字」不換算成期限，「南征吉」「利西南」不當成行程方位。

## 自我複審統計與主要修正

自我複審共修改 67 處，全部記在 `docs/review/lines-round2.json`（每處有修改前後與理由）。

- **保證語氣（62 處）**：提醒裡的「就能減少損失」「信任就會自然建立」「困境終會過去」「會帶來最大的成就」等，改為「有助於」「比較有機會」或加上條件。指出負面後果的警語（例如「太強勢會讓你失去幫助」）是提醒風險，不算保證，保留。
- **斷定現況（3 處）**：豐卦辭的提醒「事情正處於高峰」改為「若事情正處於高峰」；損上九的提醒「你已有能力」改為「若你已有能力」；睽六五的「比想像中容易」改為「可能比想像中容易」。後兩處同時去掉保證語氣。
- **不把人標成小人（2 處）**：遯卦辭的提醒「小人得勢時」改為「不正當的力量佔上風時」；解九四的白話「小人牽絆」改為「不當牽絆」。原文與小象引用的「小人」照原文保留，只在解說中轉譯。

## 載入方式

白話只在需要時載入，不進卦殿首屏（首屏仍是 127.5 KB gzip）。`lines.json` 建置成獨立的雜湊檔，`loadLines()` 以 `fetch` 載入並快取。原本規格寫 `import()`，實測 Chromium 會記住載入失敗的動態模組，同一頁面按「重試」不會重新請求，因此改用 `fetch`，並已同步修改規格。
